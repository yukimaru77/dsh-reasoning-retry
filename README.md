# dsh-reasoning-retry

返答が**出力上限（output token limit。推論も含む）に達して止まったターン**を、
**入力の出し方を変えて**やり直す [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) プラグインです。
「考えるな」「短く答えろ」とは言わず、推論の強さや出力上限も下げません。
やり直しでコンテキストを汚さないよう、失敗したステップはモデルから見える履歴から取り除きます（ログには残ります）。

## 仕組み

1. **見つける**: ターンが `max-tokens` で終わったら、その最後の返答を「失敗したステップ」とします（推論だけでも、途中まで文章やツール呼び出しを出していても同じ）。
2. **そのステップの入力を特定する**: 直前の返答より後にモデルへ入ったもの。
   - ユーザーや goal の指示 → **入力（プロンプト）**
   - ツールの実行結果 → **ツールの出力**（時刻などの差し込み情報は除く）
3. **書き換えさせる**: 同じモデルに、別の呼び出しで「入力」と「切れるまでの推論（と途中の出力）」を渡し、
   1回の返答で進められるような出し方に書き換えさせます（段階に分けて最初の段を問う、今決めることを示す、推論が既に確かめたことを前提として書く、迷っていた点を整理する、など）。内容・制約・目的は変えません。
   - プロンプトのとき: 入力そのものを書き換えた文
   - ツールの出力のとき: 出力は変えず、直後に置く短い注記（見るべき箇所、確定したこと、次に決めること）
4. **履歴を差し替えて再実行する**: DSH の surface replacement（ログに残る置き換えイベント）で
   「入力〜失敗した返答」（ツールのときは失敗した返答だけ）をモデルから見えなくし、書き換えた入力（または注記）で同じ場面から実行し直します。
5. **また上限に達したら**: 元の入力＋1回目の推論＋書き換えた入力＋2回目の推論、をすべて渡して書き換え直し、同じように差し替えて再実行します。
6. **2回やり直してもだめなら**: goal を止めて（blocked）利用者に知らせます。やり直しが通れば、止まっていた goal を再開します。

書き換えに失敗した場合は、「残りの手順を文章で書き出してから最初の1つを行う」という定型の出し方で再実行します。

## その他

- **常時の指示**（DeepSeek のモデルのみ）: 1回の返答の出力上限と、推論もそこに含まれること、段階的に進めて途中の結論を外に出すことを、モデルへの情報に足します。
- **固定された出力上限を戻す**: DSH は前回のリクエストの設定を引き継ぐため、一度だれかが下げた出力上限がセッションに残ります。以前の既定値より低い上限を見つけたら捨てて、既定値に戻します。

## 設定（`cordis.patch.yml`）

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `maxRetries` | 2 | 書き換えて再実行する回数 |
| `guidanceModels` | `deepseek` | 常時の指示を足すモデル（provider/model への正規表現。空文字で無効） |
| `rewriteInputChars` / `rewriteReasoningChars` | 12000 | 書き換え役に渡す入力・推論の文字数（先頭と末尾を残す） |
| `rewriter.maxTokens` / `rewriter.timeoutMs` | 16384 / 180000 | 書き換え呼び出しの上限 |
| `restoreAdapterMaxTokens` | true | 固定された出力上限を戻す |

## 導入

```sh
dsh plugin --profile web add "file:$PWD"
```

## テスト

```sh
node scripts/link-dsh.mjs ~/.local/share/dsh/versions/0.2.1-rc.2/node_modules   # または DSH のソースcheckout
npm test
```

テストは実際の `@deepseek-ai/dsh-session` を使い、履歴の差し替えと再実行の流れを確かめます。
